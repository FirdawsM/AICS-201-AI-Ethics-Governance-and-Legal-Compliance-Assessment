# Data dictionary: `synthetic_customers.csv`

All 8,000 records are artificially generated by `analysis/generate_data.py` (seed 42). No real person or customer is represented.

| Column | Type | Meaning |
|---|---|---|
| `customer_id` | text | Synthetic identifier (SYN00000 to SYN07999) |
| `location_type` | urban / rural | Group attribute. About 35% rural |
| `gender` | male / female | Group attribute. About 50% each |
| `income_stability` | 0 to 100 | Score for how regular income inflows are. Driven by latent creditworthiness |
| `txn_regularity` | 0 to 100 | Score for regularity of transaction patterns. Driven by latent creditworthiness |
| `months_history` | integer | Length of financial history. Shorter for rural customers and women (thin files) |
| `device_basic` | 0 / 1 | 1 = basic phone. More common in rural group (about 55% vs 15%). **Proxy feature**: unrelated to true creditworthiness |
| `location_changes_90d` | integer | Number of location changes in 90 days. Higher in rural group. **Proxy feature** |
| `hist_approved` | 0 / 1 | Past analyst decision, used as the training label. Biased against basic-phone and thin-file customers (planted) |
| `repaid_true` | 0 / 1 | Whether the customer would repay. Depends on latent creditworthiness only, not on group. Used only to evaluate fairness |

## Generation assumptions

- Latent creditworthiness has the same distribution in every group, so any outcome gap comes from features or labels, not from real differences in repayment.
- The label bias in `hist_approved` is planted deliberately so the method has something to detect. The results show how the method works. They do not show how a real system would behave.
